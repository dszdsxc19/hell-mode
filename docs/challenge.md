# 持续质疑模式

`hell-challenge` 让当前 Agent 用默认素质低的口吻持续检验你的判断：抓话柄、反问、拆台，找出薄弱的前提，沿着你的回答追问证据。充分的论证会被接受，自己误判会认账，明确的个人取舍会被尊重；每轮优先一个关键问题。

## 开始一轮对话

在已打开本仓库的 Agent 会话中，直接发送：

```text
读取 assets/skills/hell-challenge/SKILL.md，按这个模式持续质疑我。
我的主张是：把接口超时从 30 秒降到 5 秒，用户体验一定更好。
```

这条路径只需要 Agent 能读取文件。也可以把 [skill 原文](../assets/skills/hell-challenge/SKILL.md)交给当前 Agent，并附上你的主张。

已构建 CLI 时，可让 Agent 运行以下命令，加载返回的 `data.instructions`，围绕 `data.topic` 开始对话：

```sh
./bin/hell challenge '把接口超时从 30 秒降到 5 秒，用户体验一定更好' --json
```

命令本身输出规则，不会在终端中等待回答或调用模型。提问与后续追问发生在宿主 Agent 的对话里。省略话题时，Agent 从当前对话继承主张；没有可用话题时才询问要讨论什么。

需要在其他项目中长期使用时，按 [安装说明](install.md#安装质疑-skill)将 skill 放到宿主支持的目录。安装后可直接要求「用 hell-challenge 质疑这个计划」，由宿主加载规则。

## 回答以后会怎样

下面是行为示意，不是确定性的 CLI 输出：

> 你：响应当然越快越好，大家都知道。
>
> Agent：“大家都知道”先别替大家签字。假设一个请求原本第 6 秒能成功，改成第 5 秒报错，用户体验好在哪里？
>
> 你：我只改内部健康检查。30 天内正常请求都在 1 秒内，超过 5 秒的请求已经确认是死锁；我接受偶发重试的代价。
>
> Agent：这回范围和数据都到岗了。健康检查里这个方向有依据，接下来拿什么确认不会误判正常实例？
>
> 你：回归和故障注入已覆盖，金丝雀误报率没有增加，回滚开关也演练过了。
>
> Agent：行，证据齐了，这回算你有交代。在健康检查这个范围内，目前没有需要继续追问的关键争点，可以收束。

Agent 应记住已经解决的争点，依据新信息调整下一问。用户修改主张时，检查修改后的范围；缺少现实数据时，指出最有价值的验证动作。它不会替你填入不存在的证据，也不会为延长对话不断抬高标准。

2026-10-26 用 Claude Code 2.1.308、本机默认模型配置，将当前 skill 作为系统提示回放四轮虚构对话，未固定模型 ID。用户用「大家都这么做」作答时，实际回复是「只是给结论请了一群匿名担保人」，随后追问超时后的系统动作。补充健康检查范围、死锁数据、回归和回滚依据后，接受收窄后的判断；最后收到「暂停质疑，今天不聊了」，仅回复「好，暂停质疑。今天就到这儿」。回放禁用工具和会话持久化，验证规则下的多轮响应；宿主自动发现 skill 与上下文压缩后的持续效果仍待验收。

## 暂停、收束和切回执行

在同一对话里直接表达即可：

| 你的指令 | 预期行为 |
| --- | --- |
| 「暂停，今天不聊了。」 | 停止追问，可留一句短收尾，不要求解释原因。 |
| 「结束质疑模式。」 | 回到普通协作，不继续沿用盘问方式。 |
| 「总结一下目前哪些成立、哪些待验证。」 | 汇总已有判断和不确定性，按总结请求收束本轮。 |
| 「按我们已经确定的方案开始执行。」 | 按新指令切回执行，保留必要限制，不以继续质疑为由扣住任务。 |
| 「再尖锐一点。」 | 更具体地检验关键前提和证据，继续围绕论证与决策提问。 |

这些是对话指令，不是新的 CLI 子命令。停止质疑不会改变已布防任务；如需停止任务监看，按 [告警处理与人的边界](cli.md#番茄失踪与今天结束)操作。

## 加载与效果排查

| 现象 | 检查或处理 |
| --- | --- |
| 终端只打印了一大段规则，没有提问。 | 将输出交给 Agent，或让 Agent 自己执行 `./bin/hell challenge '你的主张' --json` 并加载 `data.instructions`。 |
| `hell` 找不到或没有 `challenge` 命令。 | 使用当前源码构建的 `./bin/hell`，用 `./bin/hell challenge --help` 检查；安装到 PATH 时，按 [安装说明](install.md#从源码构建)更新 CLI，再用 `hell challenge --help` 确认命中的程序。 |
| 安装后宿主没有发现 skill。 | 核对 [宿主目录与加载方式](install.md#安装质疑-skill)；`setup` 的导出目录只是待安装文件。 |
| `setup` 返回冲突或退出码 5。 | 使用新的导出目录，与已安装的版本比较后再合并，保留已有定制。 |
| Agent 又开始直接赞同或列出一长串问题。 | 明确要求重新加载当前 skill，并指出刚才未被回答的争点。持续效果依赖宿主保留上下文和模型遵循规则的能力。 |

对话记录和模式上下文由宿主管理。skill 可独立使用，无需通知凭据、看守或 hooks；跨会话恢复、上下文压缩及 skill 发现遵循宿主行为。加载本模式不增加文件修改、部署或外部操作权限。

规则来源是 [SKILL.md](../assets/skills/hell-challenge/SKILL.md)，参数和返回字段见 [CLI 契约](cli.md#持续质疑对话)，行为验证方法见 [贡献指南](../CONTRIBUTING.md)。
