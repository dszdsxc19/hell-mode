# 路线图

> **仅供娱乐。** 项目定位见 [README](../README.md)。

当前已有 Go CLI 初版。勾选项表示已有代码或对应回归；真实宿主与手机的验收情况单独列出。

## 已实现：监看任务，把人叫回来

本人约定目标、验收条件与叫人策略后开启监看。任务失联、异常结束、验收失败或超过截止时间时，独立看守按策略尝试通知；本人接管后停止本轮叫人，并能查看失败现场。

- [x] 统一核心：任务、目标契约、执行、验收与告警共用规则，使用 bbolt 持久事务状态。
- [x] Go CLI：布防预览、执行、查询、验收、事件提交、接管、暂缓、解除布防、看守与本地检查；提供 help、JSON、输入 schema 与稳定退出码。
- [x] 一个 hell-mode skill 与 Claude Code hooks 适配器：通过同一核心工作，绑定任务、执行与事件令牌；已有宿主事件样本回归。
- [x] 通用任务包装器：执行标识、退出结果、验收命令、周期心跳与私有运行日志。
- [x] 本地独立看守：截止时间、失联检测、有界调度、多进程去重、重启恢复与通知取消。
- [x] 通知插件协议：显式 manifest 注册、带版本的子进程 JSON 请求、环境变量白名单、超时与输出上限；提供 Go 类型与示例插件。
- [x] log 演练通道与 Pushover Emergency 适配器：请求、回执与取消已有本地 HTTP 回归。
- [x] 演练与现场查询：dry-run、短间隔、`watch --once`、检查输出、运行日志、通知尝试与历次告警。

## 真实使用仍需验收

- [ ] 真实 Claude Code 宿主的安装、生命周期事件，以及 skill 在真实 Agent 中的行为。
- [ ] 本人手机的触达、重复提醒、接管取消与策略耗尽。

按 [MVP 验收场景](mvp.md#首版验收场景)逐项保留实机证据。演练安排在白天；命令模拟和供应商回执都不能证明人已醒来。

当前看守是共用状态目录的本地进程。本机休眠、关机或整机故障时，它无法继续调度。远程事件服务、手机任务详情页与独立管理端授权尚未实现。

## 后续维护范围

后续围绕现有能力的可靠性、安装使用和上述实机验收维护：复现失败样本，核对重启恢复、并发去重、取消结果及安装说明。发送结果不明、宿主未覆盖的事件和手机触达缺口照实记录。

电话、清醒证明和房间联动的早期设想留在 [创作档案](brainstorm.md)，不列为后续交付安排。

## 最后，结束的决定留给人

- [x] `vanish --for 25m`：暂时失踪，约定时间到达后仍保持安静。
- [x] `back`：本人主动回来；旧任务不补发提醒，重新监看须显式 rearm。
- [x] `end`：停止看守，保留未完成的目标与证据。
- [x] `presence --json`：只读查询人的联系状态。
- [ ] 在真实宿主与本人手机上验证失踪、回来、结束及通知取消，核对已有请求的实际取消结果。

这些动作已有多任务、重启、迟到回执和并发看守回归，作用范围是同一状态目录下的 hell-mode 通知。宿主自身的权限弹窗和其他通知仍由宿主管理。
