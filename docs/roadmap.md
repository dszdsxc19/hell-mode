# 路线图

本仓库当前完成概念与设计材料。以下版本均未实现，版本号表达工作顺序，不承诺交付日期。

## v0.1 · 跑通整个体系，先把人叫回来

目标：交付一个 CLI、一个 skill、一个 Agent 宿主适配器、一个常在线看守和一个手机通道。本人能直接用命令或通过 Agent 开启监看，失败后持续收到手机提醒，并能明确接管。

- [ ] 统一核心：任务、目标契约、执行、验收与告警共用同一套规则和持久状态。
- [ ] CLI：配置与能力检查、布防预览、执行、查询、验收、事件提交、接管、暂缓、解除布防和看守启动；提供结构化输出。
- [ ] 一个 hell-mode skill：整理自然语言要求、展示需本人确认的目标与策略，通过 CLI 布防并读取状态。
- [ ] 首个宿主适配器：核对官方事件语义，至少接入一轮响应结束事件，准确绑定任务与执行；按实际能力接入等待和错误信号。
- [ ] 通用任务包装器：执行标识、退出结果、验收命令与周期心跳；与 hooks 共享任务记录。
- [ ] 常在线看守：截止时间、失联检测、持久化告警与有界通知调度。
- [ ] 第一个手机通道：优先验证 Pushover Emergency，接入回执与取消。
- [ ] 受保护的任务详情与接管、限时暂缓、解除布防入口。
- [ ] 演练模式：预览策略、测试通知、压缩时间运行全链路。
- [ ] 失败现场：目标、检查结果、日志引用与本人操作记录。

验收：完成 [MVP 验收表](mvp.md#首版验收场景)。分别从 CLI 和 skill 跑通布防，确认 hooks 与包装器事件归入同一核心；停止 Agent 后，独立看守仍按策略叫人。用本人真实手机验证失败、重复提醒、接管停止与策略耗尽。没有通过当前契约的证据，目标始终保留为未达成或无法确认。

## v0.2 · 你为什么还没接

目标：推送长期未处理时，增加本人电话和更明确的继续处理入口，并将已经验证的使用方式扩展到更多宿主。

- [ ] 选择并验证一个电话供应商：地区与号码资格、费用、回调及取消。
- [ ] 推送 → 电话的有界升级，处理无人接听、语音信箱和状态不明。
- [ ] 可选清醒证明，展示失败摘要并明确选择下一步。
- [ ] 暂缓到期重新升级，保留每次处理记录。
- [ ] 补齐首个宿主可用的等待、错误和会话恢复入口，逐项记录事件覆盖范围。
- [ ] 增加第二个 Agent 宿主适配器，复用核心、CLI、验收与通知能力。
- [ ] 按宿主提供插件安装包，包含适用的 skill、hooks 与安装说明；验收安装、更新、移除及配置保留行为。

验收：本人实机验证无人接听、接听未接管、已接管取消、费用上限；每次叫人都能追溯到具体任务与证据。不同宿主通过同一组核心回归场景，安装包只修改预览并确认的配置。

## v0.3 · 房间也开始值班

目标：把经验证有效的跨设备玩法做成可选择的模式。

- [ ] 本人配置的 Home Assistant 灯光与音箱适配。
- [ ] 电脑前签到或本轮短期二维码入口。
- [ ] 多任务失败合并队列，限制同一设备的通知总量。
- [ ] 自定义地狱文案，事实摘要与娱乐内容分开呈现。

验收：按本人设备清单回读动作结果；停止操作覆盖所有联动设备；多个任务失败不会突破全局次数和预算上限。

## 后续研究

- 停滞判定：如何区分长计算、合理等待和 Agent 原地打转。
- 验收充分性：如何补充业务证据，又保留确定性的通过条件和人工裁决。
- 看守故障：外部存活检测与独立备用通知路径。
- 远程工具调用：出现真实跨机器或工具接入需求时，再评估 MCP 接口。
- 跨设备可达性：不同手机、通知权限与网络条件下的实际触达表现。
- 夜间收益：叫醒是否缩短了处理延迟，以及误报和打扰成本。

## 决定下一个功能的依据

优先收集真实失败样本和演练证据，观察检测延迟、首次通知延迟、接管耗时、误报、重复动作及实际费用。没有回执的送达率、无法观测的「已经醒来」都标记为未知。

先验证 v0.1 核心链路，再决定哪一种更地狱的玩法值得落地。
